MS500-P4 · Flood detection积水检测

Is the curb still there?路缘还在吗？

The MS500-P4 camera watches one stretch of curb. Once a minute it compares a thin strip along the curb with dry reference images. Rain leaves the curb edge visible; standing water hides it. When the strip stops matching, the camera uploads a cropped image to Device Manager.

MS500-P4 摄像头盯着一段路缘。每分钟一次，它把路缘边上的一条窄带与晴天参考图比较。下雨时路缘边缘仍然可见，积水会把它盖住。窄带不再匹配时，摄像头把裁剪后的图片上传到 Device Manager。

This page covers the two repositories: the firmware that runs on the camera, and the simulator that runs the same C code on recorded video.

本页介绍两个仓库：在摄像头上运行的固件，以及在录像上运行同一套 C 代码的模拟器。

Concepts概念

How detection works检测原理

Frame 1920×1080画面 1920×1080→ Obstruction check遮挡检查→ Curb strip vs. gallery路缘窄带对比图库→ Correlation相关系数→ Outcome结果
Term术语Meaning含义
Curb and lane lines路缘线与车道线Two lines drawn on the web page in 1920×1080 frame coordinates: the curb line at the foot of the curb and the lane line on the road below it. The sampled curb strip is derived from them.在网页上用 1920×1080 画面坐标绘制的两条线：路缘线画在路缘根部，车道线画在其下方的路面上。取样的路缘窄带由这两条线推算。
Dry reference gallery晴天参考图库Up to 8 dry references, so each reading is compared with whichever matches the current lighting. Manual references come from Capture Baseline; the camera adds learned ones itself when a reading is confidently dry (0.65 ≤ correlation < 0.95) and a manual reference still scores at least 0.55.最多 8 张晴天参考图，每次读数与最符合当前光照的一张比较。手动参考来自“拍摄基线”；当读数明确为晴天（0.65 ≤ 相关系数 < 0.95）且至少一张手动参考仍得分 ≥ 0.55 时，摄像头会自动学习新参考。
Correlation相关系数−1 to 1: how much the curb strip still looks like the best reference. Normalized, so brightness and contrast changes don't count. Below 0.45 means submerged.−1 到 1：路缘窄带与最佳参考的相似程度。经过归一化，亮度和对比度变化不影响结果。低于 0.45 即判定为被淹没。
Severity严重程度none ≥ 0.45 > minor ≥ 0.05 > moderate ≥ −0.10 > severe
Obstruction veto遮挡否决People and vehicles found by the traffic model. If they hide 15% or more of the curb, the frame isn't used, and the camera tries a second frame. Something in the way is not evidence of a flood.交通模型检测到的人和车辆。若遮住路缘的 15% 或以上，该帧不使用，摄像头会再取一帧。被挡住不能算作积水的证据。
Shift位移校正Aligns against a patch of pavement above the curb, so a sagging camera mount doesn't look like a flood.以路缘上方的一块路面为参照对齐，避免支架下垂被误判为积水。

What a reading reports每次读数的结果

The camera takes one reading every 60 seconds, with up to 2 frames per reading.

摄像头每 60 秒读数一次，每次最多取 2 帧。

Outcome结果Meaning含义Image uploaded?是否上传图片
uploadCurb submerged: possible flood.路缘被淹没：可能积水。Yes是
heartbeatDry, but the heartbeat interval has passed since the last image. Proves the camera is alive.晴天，但距上一张图片已到心跳间隔，用于证明摄像头在线。Yes是
clearCurb visible: no flood.路缘可见：无积水。No否
blockedObstructed on both frames. An abstention, never "no flood".两帧都被遮挡。属于弃权，不代表“无积水”。No否

With an empty gallery the camera logs Dry reference gallery empty, skipping sample and reports nothing, heartbeats included. Capture a baseline first.

图库为空时，摄像头记录 Dry reference gallery empty, skipping sample，不报告任何结果，也不发送心跳。请先拍摄基线。

Set up a camera设置摄像头

  1. Open the camera's web page and choose Edit Geometry. Click the curb line's two points, then the lane line's two points, and save.打开摄像头网页，选择 Edit Geometry。依次点击路缘线的两个点、车道线的两个点，然后保存。
  2. On a dry day, press Capture Baseline on the web page, or turn on Capture Flood Baseline in Device Manager. Add more baselines later for night or other lighting.晴天时在网页上按 Capture Baseline，或在 Device Manager 中打开 Capture Flood Baseline。之后可为夜间等其他光照再添加基线。
  3. Optional: draw an upload area if the crop worked out from the lines doesn't show what you need.可选：如果由线推算的裁剪区域不合适，可以绘制上传区域。
  4. Set Flood Heartbeat Interval in Device Manager. No reboot is needed.在 Device Manager 中设置 Flood Heartbeat Interval，无需重启。

Moving the lines marks the gallery as stale. Manual references are rebuilt automatically from the baseline frames kept on the SD card.

移动线条后图库会被标记为过期，手动参考会根据 SD 卡上保存的基线帧自动重建。

Uploaded images上传的图片

Flood and heartbeat images are a crop of the raw frame, taken before any overlay is drawn and from the same frame the verdict came from. They are JPEG, quality 90.

洪水图片和心跳图片是原始画面的裁剪，在绘制任何叠加图形之前截取，并且与得出判定的是同一帧。格式为 JPEG，质量 90。

Which area is cropped裁剪哪个区域

  1. Drawn: the upload area drawn on the web page, at full resolution. Sides at least 32 px, at most 518,400 px in total (for example 960×540).手动绘制：网页上绘制的上传区域，原始分辨率。边长不小于 32 像素，总面积不超过 518,400 像素（例如 960×540）。
  2. From the lines: across the lines' width, from one curb-to-lane distance above the curb to a quarter of that distance below the lane. If it's larger than 518,400 px, every 2nd (or 3rd…) pixel is kept.由线推算：横向覆盖线条宽度，纵向从路缘线上方一个“路缘到车道”距离，到车道线下方四分之一个该距离。若面积超过 518,400 像素，则隔 2（或 3…）个像素取一个。
  3. Whole frame: at half size, only if the lines can't be used.整幅画面：缩小一半，仅在线条无法使用时。

Output sides are trimmed to whole 8-pixel blocks. With the default lines the crop is 1360×360 at full resolution, as in the picture at the top.

输出边长裁到 8 像素的整数倍。使用默认线时，裁剪结果为 1360×360、原始分辨率，见页首图示。

洪水检测固件的网页显示 CURB、LANE 线和上传区域（手动绘制为实线，由线推算为虚线）、图库状态，以及以下按钮：Edit Geometry、Capture Baseline、View Current Baseline、Draw Upload Area（也可重新绘制）和 Delete Upload Area。

Build and flash编译与烧录

ESP-IDF v5.4.3 for the ESP32-P4. Choose the flood model with idf.py menuconfig → Project AS → DNN Model Type (CONFIG_DNN_TYPE_FLOOD).

使用 ESP-IDF v5.4.3，目标芯片 ESP32-P4。通过 idf.py menuconfig → Project AS → DNN Model Type 选择洪水模型（CONFIG_DNN_TYPE_FLOOD）。

. $HOME/esp/v5.4.3/esp-idf/export.sh
idf.py reconfigure        # after adding source files (main/CMakeLists.txt globs them)
idf.py build
idf.py -p PORT app-flash  # program only: keeps lines, gallery and baseline
idf.py -p PORT monitor

A plain idf.py flash erases the camera's saved lines, gallery and baseline. main/CMakeLists.txt flashes the storage (/spiffs) and storage_dl (/download) images from spiffs_data/ and spiffs_download/. The camera then falls back to the default lines and skips every reading until a baseline is captured again. Use app-flash or OTA on a camera that's already set up.

直接执行 idf.py flash 会清除摄像头已保存的线、图库和基线。main/CMakeLists.txt 会用 spiffs_data/ 和 spiffs_download/ 烧写 storage（/spiffs）和 storage_dl（/download）分区。之后摄像头回到默认线，并跳过所有读数，直到重新拍摄基线。已设置好的摄像头请使用 app-flash 或 OTA。

Install安装

The simulator compiles the firmware's detection C code unmodified, straight from the firmware checkout, and runs it on videos, images or folders of images. Windows with Git Bash; needs MinGW gcc, CMake 3.20 or later, Ninja and Python 3.11.

模拟器直接从固件目录编译未经修改的检测 C 代码，在视频、图片或图片文件夹上运行。环境为 Windows + Git Bash，需要 MinGW gcc、CMake 3.20 及以上、Ninja 和 Python 3.11。

py -3.11 -m venv .venv
.venv/Scripts/python -m pip install -e ".[dev,onnx]"   # onnx runs models/traffic.onnx, the camera's model
export FLOOD_FIRMWARE_DIR=/d/git/NETWORK_P4_FLOOD_DETECTION   # optional: another firmware checkout

The native library rebuilds itself whenever a firmware or shim source is newer than build/native/flood_core.dll. Copy models/traffic.onnx in by hand (it isn't in git), or run with --no-detector.

当固件或适配层源码比 build/native/flood_core.dll 新时，原生库会自动重新编译。models/traffic.onnx 不在 git 中，需要手动复制；否则使用 --no-detector 运行。

Run folder and uploads运行目录与上传图片

In device mode each upload or heartbeat reading writes the image the camera would have sent: the same crop (the drawn --upload-area, else the one derived from the curb and lane lines), the same file name, and a .json beside it holding the camera's description. Names and descriptions come from the firmware's own flood_upload_meta.c.

在 device 模式下，每次 upload 或 heartbeat 读数都会写出摄像头本应发送的图片：相同的裁剪区域（手动绘制的 --upload-area，否则由路缘线和车道线推算）、相同的文件名，以及旁边一个保存摄像头描述的 .json 文件。文件名和描述来自固件自己的 flood_upload_meta.c。

out/run1/uploads/MS500-H120-EP-2614-1001_flood_20261022_220133.jpg
out/run1/uploads/MS500-H120-EP-2614-1001_flood_20261022_220133.json   # same JSON as i_description

The upload crop, file names and descriptions are identical: they are compiled from the firmware's flood_upload_roi.c and flood_upload_meta.c. Only the JPEG encoder differs:

上传裁剪、文件名和描述完全一致：它们由固件的 flood_upload_roi.c 和 flood_upload_meta.c 编译而来。只有 JPEG 编码器不同：
